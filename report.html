1. Цель работы

Приобретение практических навыков создания серверного приложения на Node.js с Express.js: маршрутизация, обработка GET, POST, PUT и DELETE, валидация данных и формирование HTTP-ответов для дальнейшей интеграции с клиентской частью.

2. Описание проекта

Сервер управляет записями об оценках учеников. Ресурс называется grades. Каждая запись содержит id, имя ученика student, предмет subject, оценку value, дату date и комментарий comment. Оценки задаются целыми числами от 2 до 5. student и subject обязательны и ограничены 100 символами; date является существующей календарной датой в формате YYYY-MM-DD. Комментарий необязателен, до 1000 символов. Неизвестные поля запрещены.

Данные хранятся в массиве в памяти процесса. При старте массив пуст, при перезапуске все записи теряются. Идентификаторы назначаются сервером и не переиспользуются в течение работы процесса. Отдельные сущности учеников, предметов, классов и учетных записей могут быть добавлены в следующих работах.

server.js             Express, middleware, запуск сервера
routes/grades.js       маршруты ресурса
controllers/grades.js валидация и CRUD
models/grades.js       массив и генератор идентификаторов
test/grades.test.js    автоматические HTTP-тесты
requests.http         запросы для REST Client
package.json          зависимости и команды запуска

3. Запуск

Требуется Node.js 22 или новее. Команды выполняются в каталоге проекта:

npm ci --include=dev
npm run dev
# Обычный запуск: npm start
# Проверка: npm test

Адрес: http://localhost:3000. Порт можно изменить переменной окружения PORT; в PowerShell: $env:PORT = '3001'. Для ручных проверок используется встроенный файл requests.http: установите расширение REST Client (идентификатор humao.rest-client), откройте файл в VS Code и нажмите Send Request над нужным запросом. Запрос POST имеет имя createGrade, поэтому идентификатор из его ответа автоматически используется в последующих GET, PUT и DELETE запросах. Подробная инструкция находится в rest-client.md.

4. Маршруты

В таблице G обозначает объект записи: {"id":1,"student":"Ivan Petrov","subject":"Mathematics","value":5,"date":"2026-09-09","comment":"Homework"}. Тело B содержит те же поля без id.

МетодПример запросаУспех и ответОшибки
GET/grades200, [G] или []400 при неверных фильтрах
GET/grades?subject=Mathematics200, [G] или []400 при неверных фильтрах
GET/grades/1200, G400: неверный ID; 404: запись отсутствует
POST/grades, тело B201, G; Location: /grades/1400: неверные данные
PUT/grades/1, тело B с value: 4200, обновленный G400: неверные данные или ID; 404: запись отсутствует
DELETE/grades/1204, без тела400: неверный ID; 404: запись отсутствует

Фильтры student и subject сравниваются полностью без учета регистра и могут применяться совместно. PUT требует все обязательные поля; отсутствие comment сбрасывает его в пустую строку. Ошибки имеют вид {"error":"Grade not found"}. Неизвестный маршрут возвращает 404, поврежденный JSON — 400, тело свыше 100 КБ — 413, непредвиденная ошибка — 500 без раскрытия стека клиенту.

5. Основные части server.js

const express = require('express');
const gradeRoutes = require('./routes/grades');
const app = express();
app.use(express.json({ limit: '100kb' }));
app.use(express.urlencoded({ extended: false, limit: '100kb' }));
app.use('/grades', gradeRoutes);

app.use((req, res) => {
  res.status(404).json({ error: 'Route not found' });
});

app.use((err, req, res, next) => {
  if (res.headersSent) return next(err);
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json({ error: 'Invalid JSON body' });
  }
  if (err.status >= 400 && err.status < 500) {
    return res.status(err.status).json({ error: 'Invalid request body' });
  }
  console.error(err);
  res.status(500).json({ error: 'Internal server error' });
});

if (require.main === module) {
  const port = process.env.PORT || 3000;
  app.listen(port, () => console.log(`Server running at http://localhost:${port}`));
}
module.exports = app;

CRUD вынесен в контроллер. Например, удаление найденной записи:

exports.remove = (req, res) => {
  grades.splice(grades.indexOf(req.grade), 1);
  res.status(204).end();
};

Проверка ID и поиск записи выполняются в router.param перед обработчиком отдельного ресурса.

7. Ответы на контрольные вопросы

  1. HTTP-методы. GET читает список или отдельную оценку, POST создает запись, PUT полностью обновляет запись, DELETE удаляет ее.
  2. Параметры. Параметр маршрута /grades/:id доступен через req.params.id, строка запроса ?subject=Mathematics — через req.query.subject. Значения необходимо валидировать.
  3. express.json(). Разбирает тело запроса с Content-Type: application/json и помещает результат в req.body. Не заменяет валидацию полей.
  4. Статусы. При создании возвращается 201 Created, при удалении — 204 No Content без тела ответа.
  5. REST API. Интерфейс, организованный вокруг ресурсов. Основные ограничения REST: клиент-серверная архитектура, отсутствие состояния клиентской сессии между запросами на сервере, кэшируемость, единообразный интерфейс, слоистая система и необязательная загрузка исполняемого кода. Ресурсы идентифицируются URI; HTTP-методы имеют стандартную семантику. Хранение самих ресурсов на сервере не нарушает stateless.
  6. Глобальная обработка ошибок. После маршрутов регистрируется middleware с четырьмя аргументами (err, req, res, next). Ошибки передаются через next(err); Express 5 также передает отклонения Promise из async-обработчиков. Неизвестные маршруты отдельно обрабатываются обычным middleware.
  7. Формат ошибок. Выбран единый JSON-объект с полем error, например {"error":"Grade not found"}. HTTP-статус сообщает категорию ошибки.
  8. Повторный DELETE. Отправить DELETE по тому же URL повторно. Первый запрос возвращает 204, следующий — 404. Идемпотентность сохраняется: состояние ресурса после обоих запросов одинаково, запись отсутствует.
  9. nodemon. Следит за файлами и перезапускает приложение после изменений. Это ускоряет разработку, но при данном хранении приводит к очистке массива.
  10. PUT и PATCH. PUT полностью заменяет данные ресурса, PATCH изменяет отдельные поля. Реализован PUT по заданию: все обязательные поля должны присутствовать, необязательный комментарий при отсутствии становится пустым.
  11. CORS. Можно установить пакет cors и зарегистрировать app.use(cors({ origin: 'http://localhost:5173' })) перед маршрутами. Middleware добавит заголовки доступа и обработает preflight. В рабочей системе следует разрешать конкретные доверенные origin. CORS не заменяет аутентификацию.
  12. Массив вместо БД. Он позволяет сосредоточиться на HTTP и маршрутах без настройки БД. База данных нужна для сохранения данных после перезапуска, совместной работы нескольких процессов, связей между сущностями и транзакций.
  13. Content-Type. Для JSON устанавливается Content-Type: application/json. URL-encoded middleware также подключен, но числовая оценка в этом API должна передаваться JSON-числом.
  14. Пример curl. Для Bash или PowerShell 7.3+: 
    curl -i -X POST http://localhost:3000/grades -H 'Content-Type: application/json' -d '{"student":"Ivan Petrov","subject":"Mathematics","value":5,"date":"2026-09-09","comment":"Homework"}'
    В Windows PowerShell 5.1 используйте curl.exe с телом из файла, чтобы избежать особенностей передачи кавычек: 
    curl.exe -i -X POST http://localhost:3000/grades -H "Content-Type: application/json" --data-binary "@example-grade.json"
  15. Проверки после изменений. Выполнить npm test, дождаться перезапуска nodemon, проверить актуальные маршруты через REST Client и просмотреть ошибки в терминале. Проверять как успешные запросы, так и некорректные данные и отсутствующие ID.
  16. Запуск на другом компьютере. Установить Node.js 22+, клонировать репозиторий, перейти на lab21 и выполнить npm ci --include=dev, затем npm start или npm run dev. При необходимости задать PORT. Исходные данные в памяти не переносятся.
